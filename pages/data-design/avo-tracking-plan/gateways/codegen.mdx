# Gateways in Avo Codegen

_A gateway is a destination of every source that feeds it. Your source sends its events to the gateway, and the gateway sends them on to its outputs._

<Callout type="info" emoji="🚧">
  Gateways are in closed beta. Reach out at [support@avo.app](mailto:support@avo.app) or in the chat bubble in the app to request access and share feedback.
</Callout>

When a source is an input of a [gateway](/data-design/avo-tracking-plan/gateways), [Avo Codegen](/implementation/avo-codegen-overview) adds the gateway to that source's generated code as a [custom destination](/reference/avo-codegen/destinations), named after the gateway. You implement it once, the same way as any other destination interface, to hand events to your gateway: a `dataLayer.push` for Google Tag Manager, `analytics.track` for Segment, or a request to your own pipeline.

## What your source's code gets

For a gateway called **GTM** with your Web source as an input:

- `initAvo` takes a `GtmDestination` parameter, typed by the same `CustomDestination` interface as every custom destination.
- Every event and variant the Web source sends to the gateway calls it, under its name in the tracking plan.
- The destinations the gateway sends to, such as Google Analytics 4 or Meta, don't appear in the source's code once you disconnect them from the source. The gateway sends to them.

```typescript
import Avo, { AvoEnv } from "./Avo";

const gtmDestination = {
  logEvent: (eventName: string, eventProperties: Record<string, any>) => {
    window.dataLayer.push({ event: eventName, ...eventProperties });
  },
};

Avo.initAvo({ env: AvoEnv.Prod }, {}, gtmDestination);
```

Custom destinations are passed to `initAvo` in order, so check where the gateway's parameter sits after you pull.

## Choose which events go to the gateway

You pick the events a gateway gets the same way as for a destination. On an event, each source lists the gateways it feeds next to its destinations, marked **(gateway)**, and you turn each one on or off for that event. A variant can turn the gateway on or off for its source too, under its source overrides.

When you connect a source to a gateway, every event the source sends is turned on for the gateway. Turn off the events the gateway shouldn't get, and they stay out of the gateway's calls in your source's code. An event turned off for the gateway also doesn't reach the gateway's checkpoints in Inspector.

## Move destinations behind a gateway

When a gateway starts sending to destinations your source used to send to directly, set the plan up like this, on one branch:

1. **Disconnect those destinations from the source**, in the source's settings. A destination still connected to the source gets its events directly from your code as well as from the gateway, so it receives them twice.
2. **Connect the source to the gateway** as one of its inputs. Every event the source sends is turned on for the gateway, so turn off any it shouldn't get.
3. **Connect the destinations to the gateway** as its outputs, such as Google Analytics 4 and Meta.
4. **Pull the code** with `avo pull [--branch my-branch] [SourceName]`, then pass your gateway implementation to `initAvo` and remove the implementations of the destinations you disconnected.

### Replacing a custom destination with a gateway

If you modelled your tag manager as a custom destination, such as a **Web Data Layer** destination that pushes to `dataLayer`, the gateway takes its place. The interface is the same, so you can pass your existing implementation as the gateway's destination and remove the old destination from the plan.

### Name mappings

A name mapping set for one destination, such as sending `Client` as `client_ga4` to Google Analytics 4 only, is applied by your source's code only while that destination is connected to the source. Once the gateway sends to it, add the rename as a [transformation](/data-design/avo-tracking-plan/gateways/transformations) on that output instead, so the destination keeps receiving the same name.

Your source sends the gateway the names from the tracking plan. A name mapping set for all destinations still applies, so the gateway receives the mapped name.
