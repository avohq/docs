# Configuring Inspector Gateways

_Add Avo Inspector at the gateway, at each output, or both, so Avo can check what each checkpoint actually receives._

<Callout type="info" emoji="🚧">
  Gateways are in closed beta. Reach out at [support@avo.app](mailto:support@avo.app) or in the chat bubble in the app to request access and share feedback.
</Callout>

Inspector checks that the events your gateway handles match the design in your tracking plan. There are two kinds of checkpoint, and you can add Inspector at either or both:

- **At the gateway**: one checkpoint that sees every event after the gateway's own transformations, before anything output-specific happens. Leave the output reference empty here.
- **At each output**: one checkpoint per destination that sees the event after that output's transformations. Set the output reference to that output's reference, such as `meta-7f3k2q`.

Start by [setting up the gateway](/data-design/avo-tracking-plan/gateways/set-up-a-gateway) in your tracking plan. One Inspector API key covers the whole gateway. Find it in Avo on the **Sources** page, under **Gateways**: open the gateway and go to the **Inspector setup** tab. The tab shows these steps for your gateway type, with your key and each output's reference already filled in. For each output, it gives you a snippet, script or function to copy with **Copy**. An output without a reference shows **No output reference set yet**.

## Tell Avo which source an event came from

A gateway usually receives events from several sources, so every event needs an **origin hint**: a value that names the source it came from, such as `web`, `ios` or `android`. Keep it to a few fixed values, and never use a user id. Without an origin hint, Avo can't tell which source an event came from, so it doesn't check the event against your design.

Set it up in two places:

1. **In Avo, map each value to a source.** On the **Sources** page, open each source that feeds the gateway, go to its **Inspector setup** tab and add the value under **Origin hints**. Each value can belong to one source only, and the match is exact and case-sensitive. You can also map a value from the issue Inspector raises when it sees one it doesn't know. See [Fix gateway issues](#fix-gateway-issues).
2. **In your Inspector setup, send the value on every event.** Each setup below has an origin hint field. Fill it in on every event, even where it's labelled optional. Send that source's app version as well. With an origin hint set, events without an app version are recorded without a version.

## Set up your gateway

<Tabs items={['Server-side GTM', 'Web GTM', 'C#', 'Node.js', 'Java', 'Go', 'Segment', 'RudderStack']}>
<Tabs.Tab>

1. **Copy the key** from the Inspector setup tab.
2. **Add the tag template.** In your server container, open **Templates**, choose **Search Gallery** under **Tag Templates** and add the Avo Inspector tag template. If it's already there, update it. Paste the key into **Avo Inspector Key** and choose the **Environment** (development, staging or production).
3. **Inspect at the gateway.** Add an Avo Inspector tag with **Output reference (optional)** left empty, fired by a **Custom Event** trigger whose event name matches the regex `.*` so it sees every event. In the tag's **Transformations** section, apply the gateway-level transformations and none of the output-specific ones. With no gateway-level transformation, inspect the event as received.
4. **Inspect each output.** Add one Avo Inspector tag per destination with the same triggers as that destination's tag, and set **Output reference (optional)** to that output's reference. In the tag's **Transformations** section, apply the same transformations as the destination tag.
5. **Set the origin hint.** On every Avo Inspector tag, set **Origin hint (optional)** to an Event Data variable that names the source, such as `{{Event Data - platform}}`. Set **Origin app version (optional)** to that source's app version.

The environment is fixed per tag. Use a separate tag, or a lookup variable, if one container serves several environments.

Events you send while testing in GTM Preview go to development, whatever the **Environment** setting, while **Send to the development environment in Preview mode** is checked. It's checked by default, and live traffic keeps using **Environment**. A tag saved before this setting existed keeps sending Preview events to its **Environment** until you open the tag and save it again.

<Tabs.Tab>

1. **Copy the key** from the Inspector setup tab.
2. **Add the tag template.** In your web container, open **Templates**, search the gallery for **Avo Inspector** by Avo and add it to the workspace. If it's already there, update it. Paste the key into **Inspector API Key**.
3. **Inspect at the gateway.** Add one Avo Inspector tag on the **All Custom Events** trigger with **Output reference (optional)** left empty. If the gateway has its own transformations, apply them before pushing the event to the dataLayer so this tag reads the transformed event.
4. **Inspect each output.** Add one more Avo Inspector tag per destination, firing on the same triggers as that destination's tag, and set **Output reference (optional)** to that output's reference. You don't need tag sequencing: the tag reads the same dataLayer event the destination tag fires on.
5. **Set the origin hint.** On every Avo Inspector tag, set **Origin hint (optional)** to a Data Layer Variable that names the source in a few fixed values, and point **Origin app version (optional)** at that source's app version variable.

Events sent while you test in GTM Preview are recorded as development.

<Tabs.Tab>

Use the Avo Inspector C# SDK in the service that acts as your gateway. Create one `AvoInspector` per gateway with the key. In your handler, read the event's origin hint and app version once. Then call `TrackSchemaFromEvent` once after the gateway's own transformation, with no output reference, and once per output after that output's transformation, with that output's reference. Flush before the process exits.

```csharp
// Once per gateway
var inspector = new AvoInspector(new AvoInspectorOptions
{
    ApiKey  = "YOUR_GATEWAY_INSPECTOR_KEY",
    Env     = AvoInspectorEnv.Dev,  // Dev, Staging or Prod
    Version = "1.0.0",  // your gateway's version
    AppName = "my-gateway",
});

// eventProperties, gatewayProperties and transformedProperties are IDictionary<string, object?>

// Once per event: the source it came from and its app version
var originHint = eventProperties.TryGetValue("platform", out var platform) ? platform as string : null;
var originAppVersion = eventProperties.TryGetValue("appVersion", out var appVersion) ? appVersion as string : null;

// At the gateway: the event after the gateway's own transformation, before fan-out
await inspector.TrackSchemaFromEvent(
    eventName,
    gatewayProperties,
    outputReference: null,
    originHint: originHint,
    originAppVersion: originAppVersion);

// At each output: the event after that output's transformation
await inspector.TrackSchemaFromEvent(
    eventName,
    transformedProperties,
    outputReference: "meta-7f3k2q",
    originHint: originHint,
    originAppVersion: originAppVersion);

// Before the process or handler returns
await inspector.Flush();
```

Replace `platform` and `appVersion` with the properties that name the source and carry its app version.

Use the [Avo Inspector Node.js SDK](https://www.npmjs.com/package/node-avo-inspector) 2.0 or later in the service that acts as your gateway. Create one `AvoInspector` per gateway with the key. In your handler, read the event's origin hint and app version once. Then call `trackSchemaFromEvent` once after the gateway's own transformation, without an output reference, and once per output after that output's transformation, with that output's reference. Flush before the process exits.

```javascript
// npm i node-avo-inspector@2
import { AvoInspector, AvoInspectorEnv } from "node-avo-inspector";

// Once per gateway
const inspector = new AvoInspector({
  apiKey: "YOUR_GATEWAY_INSPECTOR_KEY",
  env: AvoInspectorEnv.Dev, // Dev, Staging or Prod
  version: "1.0.0", // your gateway's version
  appName: "my-gateway",
  // disableBatchTimer: true, // in a serverless function
});

// Once per event: the source it came from and its app version
const originHint = typeof eventProperties?.["platform"] === "string" ? eventProperties["platform"] : undefined;
const originAppVersion = typeof eventProperties?.["appVersion"] === "string" ? eventProperties["appVersion"] : undefined;

// At the gateway: the event after the gateway's own transformation, before fan-out
await inspector.trackSchemaFromEvent({
  eventName,
  eventProperties: gatewayProperties,
  originHint,
  originAppVersion,
  // no output reference: this is the gateway checkpoint
});

// At each output: the event after that output's transformation
await inspector.trackSchemaFromEvent({
  eventName,
  eventProperties: transformedProperties,
  outputReference: "meta-7f3k2q",
  originHint,
  originAppVersion,
});

// Before the process or serverless handler returns
await inspector.flush();
```

Replace `platform` and `appVersion` with the properties that name the source and carry its app version.

Use the [Avo Inspector Java SDK](/reference/avo-inspector-sdks/java) 2.0 or later in the service that acts as your gateway. Create one `AvoInspector` per gateway with the key. In your handler, read the event's origin hint and app version once. Then call `trackSchemaFromEvent` once after the gateway's own transformation, without an output reference, and once per output after that output's transformation, with that output's reference. Flush before the process exits.

```java
// Gradle, with maven { url 'https://jitpack.io' } in repositories:
// implementation 'com.github.avohq:java-avo-inspector:2.0.0'
import is.avo.inspector.AvoInspector;
import is.avo.inspector.AvoInspectorEnv;
import is.avo.inspector.AvoInspectorOptions;
import is.avo.inspector.InspectorEvent;

// Once per gateway
AvoInspector inspector = new AvoInspector(AvoInspectorOptions.builder()
        .apiKey("YOUR_GATEWAY_INSPECTOR_KEY")
        .env(AvoInspectorEnv.Dev) // Dev, Staging or Prod
        .appVersion("1.0.0") // your gateway's version
        .appName("my-gateway")
        .build());

// Once per event: the source it came from and its app version
Object platform = eventProperties.get("platform");
String originHint = platform instanceof String ? (String) platform : null;
Object appVersion = eventProperties.get("appVersion");
String originAppVersion = appVersion instanceof String ? (String) appVersion : null;

// At the gateway: the event after the gateway's own transformation, before fan-out
inspector.trackSchemaFromEvent(InspectorEvent.builder() // no output reference: this is the gateway checkpoint
        .eventName(eventName)
        .eventProperties(gatewayProperties)
        .originHint(originHint)
        .originAppVersion(originAppVersion)
        .build());

// At each output: the event after that output's transformation
inspector.trackSchemaFromEvent(InspectorEvent.builder()
        .eventName(eventName)
        .eventProperties(transformedProperties)
        .outputReference("meta-7f3k2q")
        .originHint(originHint)
        .originAppVersion(originAppVersion)
        .build());

// Before the process or handler returns
inspector.flush();
```

Replace `platform` and `appVersion` with the properties that name the source and carry its app version.

Use the Avo Inspector Go SDK v2 in the service that acts as your gateway. Create one inspector per gateway with `NewAvoInspector` and the key. In your handler, read the event's origin hint and app version once. Then call `TrackSchemaFromEvent` once after the gateway's own transformation, without an output reference, and once per output after that output's transformation, with that output's reference. Flush before the process exits: Go has no exit hook, so nothing else sends what is still buffered.

```go
// go get github.com/avohq/go-avo-inspector/v2
import (
	"context"
	"log"

	avoinspector "github.com/avohq/go-avo-inspector/v2"
)

// Once per gateway
inspector, err := avoinspector.NewAvoInspector(
	"YOUR_GATEWAY_INSPECTOR_KEY",
	avoinspector.Dev, // Dev, Staging or Prod
	"1.0.0", // your gateway's version
	"my-gateway",
)
if err != nil {
	log.Fatal(err)
}

// Once per event: the source it came from and its app version
originHint, _ := eventProperties["platform"].(string)
originAppVersion, _ := eventProperties["appVersion"].(string)

// At the gateway: the event after the gateway's own transformation, before fan-out.
// No output reference: this is the gateway checkpoint.
if _, err := inspector.TrackSchemaFromEvent(avoinspector.InspectorEvent{
	EventName:        eventName,
	EventProperties:  gatewayProperties,
	OriginHint:       originHint,
	OriginAppVersion: originAppVersion,
}); err != nil {
	log.Print("Avo Inspector track: ", err)
}

// At each output: the event after that output's transformation
if _, err := inspector.TrackSchemaFromEvent(avoinspector.InspectorEvent{
	EventName:        eventName,
	EventProperties:  transformedProperties,
	OutputReference:  "meta-7f3k2q",
	OriginHint:       originHint,
	OriginAppVersion: originAppVersion,
}); err != nil {
	log.Print("Avo Inspector track: ", err)
}

// Before the process or handler returns
if err := inspector.Flush(context.Background()); err != nil {
	log.Print("Avo Inspector flush: ", err) // some events may not have been sent
}
```

Replace `platform` and `appVersion` with the properties that name the source and carry its app version.

<Tabs.Tab>

At the top of the Inspector setup tab, pick the **Environment** and the **Inspection scope**: **Event properties** (the default), **Event properties and context**, or **Everything the warehouse stores**. The tab fills both into everything it generates, so the gateway and its outputs report to the same environment and inspect the same fields.

1. **Inspect at the gateway.** In Segment, add the **Avo Inspector v2** destination to each source that sends to this gateway. Paste the key into **Avo Inspector API Key**, set **Environment** and **Gateway Inspection Scope** to what you picked, and make sure **Gateway Support** is on. It's on by default for new destinations, so turn it on if you added the destination earlier. Keep one **Track Schema From Event** mapping and leave its **Output Reference** empty. This checkpoint sees every track event as Segment receives it, before any destination's own mappings or filters.
2. **Inspect each output.** The tab generates an Insert Function for each output. For each one, open Segment's Functions catalog, choose **New Function**, then **Insert**, and paste the code. Under **Connect a destination**, pick that output's destination. Then turn on **Enable Function** in the destination's **Functions** tab.
   - If the destination already has an insert function, move its code into `applyYourInsertFunction`, and the code of an `onBatch` handler into `applyYourBatchInsertFunction`.
   - Avo inspects what the function returns: the event after the destination's filters, before its field mappings. A property that an Actions destination's **Mappings** rename, reshape or drop isn't visible to Inspector.
   - Insert functions only work with cloud-mode destinations. Segment can't attach one to a device-mode destination, or to a storage destination such as a warehouse.
   - With **Batch events** on (the default), each function sends a whole batch to Avo in one request. Segment holds events for up to 10 seconds to form a batch, so delivery to the destination can lag by that much. Turn it off to have each function wait for Avo's answer on every track event instead. Either way, each request can add up to a second of billed function time.
3. **Set the origin hint.** Give each Segment source a label, such as `ios-app`, and map each label to a source in Avo. Set it as **Origin Hint** on the **Track Schema From Event** mapping, and as **Avo Origin Hint** on each Insert Function: open the function's **Settings** tab, add a setting with that label (Segment names it `avoOriginHint`) and leave **Required** off. If one source carries events from several apps or platforms, map **Origin Hint** to a path instead, such as `$.context.app.name`. The function's setting holds one value for every event, so also edit `getOriginHint` in each Insert Function to read the same field, such as `event.context.app.name`.

The destination reads the app version from the event property named in its **App Version Property** setting, or else from the mapping's **App Version** field, `$.context.app.version` by default. Each Insert Function's `getAppVersion` reads `event.context.app.version`, which only mobile sources send. For a web source, edit it to read the property that carries the version first, such as `event.properties.app_version`.

At the top of the Inspector setup tab, pick the **Environment** and the **Inspection scope** before you copy the scripts. The tab generates one script for the gateway and one for each output. Every script already contains your key.

1. **Inspect at the gateway.** In RudderStack, create a transformation from the **Gateway checkpoint script** and connect it to a destination you add only for Inspector, with no other transformation. An output script whose `AVO_OUTPUT_REFERENCE` is empty sends nothing to Avo until you paste the reference in.
3. **Set the origin hint.** In every script, make `getOriginHint` return a value that names the source in a few fixed values, such as `event.context.library.name`. `getAppVersion` returns `event.context.app.version`. Change it if the source sends its version somewhere else, such as in a property.

## Check that events arrive

Send a few test events through the gateway in development. Then open the [Inspector Debugger](/inspector/inspector-debugger) to see each event at each checkpoint:

- **Checkpoint.** The **Checkpoint** column shows where the event was inspected: the gateway's name at the gateway, and the gateway and destination, such as `Server-side GTM → Meta`, at an output.
- **Pass or fail.** Each event is checked against what its checkpoint should receive. Open an event to see its checkpoint, its origin hint, and how many issues it has there, with a link to them. An event that hasn't been checked shows **Not checked yet**.
- **Filter by checkpoint.** Pick one or more sources, gateways and gateway outputs in the **Checkpoint** filter.
- **Follow one session.** Pick several streams, such as a source's stream and the gateway's stream, to see one session's events on their way through the pipeline.

The Debugger checks events against the branch you're viewing, so you can try an origin hint or a transformation on a branch before you merge it. Issues at each checkpoint show up in the [Issues view](/inspector/inspector-issues-view), checked against your main branch.

## Fix gateway issues

As well as issues with the events themselves, Inspector raises two kinds of issue about the gateway setup:

- **Origin hint not mapped to a source.** Events reached the gateway with an origin hint that no source claims, so Avo can't check them against a source. Open the issue and, under **Fix**, pick the source that sends the hint and choose **Assign to** that source. If the source isn't an input on the gateway yet, assigning adds it. On a branch, the change applies once the branch is merged. If events arrive with no origin hint at all, the issue says so and links to how to send one.
- **Unknown gateway or gateway output.** Events arrived with an output reference that matches no output on the gateway, or with the key of a gateway that isn't in your tracking plan. If you renamed the output, update the output reference in your tag or code. If you removed it by mistake, add it back. A gateway that only exists on an open branch shows this issue until the branch is merged.

[Slack alerts](/inspector/inspector-slack-alerts) for gateway issues name the gateway and the output, or say the issue happened at the gateway, before any output.
